## Подробности

### agent-desktop
- Установка через `npm install -g agent-desktop`. Установщик предупредил, что postinstall-скрипт пропущен (`install-scripts`). Команда `agent-desktop status` работает, значит бинарь на месте. Если появятся проблемы, разберём отдельно.
- `list-windows` показывает все окна, в том числе скрытые (`visible: false`). Агент работает с видимыми.
- Ошибки, которые стоит учитывать в коде:
  - `WINDOW_NOT_FOUND` — приложение запущено, но окна нет (Finder и Telegram в текущем состоянии).
  - `AMBIGUOUS_TARGET` — у приложения два окна (Safari). Нужен `--window-id`.

### Чтение содержимого
- **Системные настройки:** `snapshot --app "Системные настройки" -i --compact` вернул дерево с `ref_id` для каждого элемента и списком `available_actions`. Это подтверждает модель «наблюдай → ссылка → действие».
- **Safari, веб-страница:** `snapshot --app Safari --window-id w-3933 -i --compact` вернул текст страницы (заголовки, названия ячеек). Чтение веб-контента работает.

### Obsidian
- Порт 27123 отвечает. Проверку записи заметки сделаем, когда появится API-ключ, который нужно положить в переменные окружения или Keychain, а не в репозиторий.

### Ollama
- Модель `qwen3-vl:8b` уже установлена. Она подходит для проверки «визуального пути» (фаза 3), если дерево элементов окажется пустым в каком-то приложении.

### Голос
- Не измерен. Нужны whisper.cpp (через Homebrew) и модель Whisper. Размер модели выберем по замеру задержки и качества русского.

### Вторая проверка (окна открыты автором)
- **Finder:** дерево окна «Обучение» читается полностью: 83 ref-а, 75 текстовых узлов (боковое меню, «Недавние», «Избранное», «Яндекс.Диск»).
- **Telegram (macOS, «Telegram @ Павел»):** окно видно (`visible: true`, `accessible: true`), но дерево содержит только корень `window`, `subtree_truncated: true`, 0 ref-ов.
  - Повторные попытки: после `focus-window`, с `--timeout-ms 15000`, с `--skeleton`. Результат тот же.
  - Вывод: Telegram Desktop на macOS не отдаёт содержимое чата через accessibility в том виде, в котором нужно. Это подтверждается тем, что приложение рисует свой интерфейс, а не использует нативные элементы.
- **Что это значит для продукта:** сценарий S1 («Луна, что ответить начальнику») нельзя строить только на accessibility для Telegram. Нужны другие пути:
  1. **Визуальный:** скриншот окна и распознавание текста или модель с изображениями (например, `qwen3-vl:8b` локально). Это запасной путь из фазы 3.
  2. **Telegram API (TDLib):** официальная библиотека для клиентов. Читает и отправляет сообщения от имени аккаунта пользователя. Это надёжнее, но требует отдельной авторизации и соблюдения условий Telegram.
  3. **Комбинация:** TDLib для чтения и отправки, accessibility для остальных приложений.
- **Решение:** проверяем TDLib в фазе 3 как основной путь для Telegram. Визуальный путь остаётся как запасной для приложений, где accessibility не работает.

## Что нужно от автора, чтобы закрыть фазу 0

1. Открыть окно **Telegram** с чатом (любой, например, с тестовым контактом).
2. Открыть окно **Finder**.
3. Дать ключ Obsidian Local REST API любым безопасным способом (например, `export OBSIDIAN_API_KEY=...` в своём терминале, без записи в файлы репозитория).
4. Разрешить вызов установки голосовой модели, когда дойдём до замера голоса.

После этих шагов перезапускаю проверки Finder, Telegram, Obsidian и голоса, и дописываю результаты в этот файл.

## Ограничения, которые уже видны

- Окна, которые свёрнуты или на другом рабочем столе (Space), агент может не видеть. Это надо учитывать в UX: Луна должна сказать, что окна не видно, а не молчать.
- Сам факт «приложение запущено» не означает, что окно доступно для чтения.
