# Аудит кода Luna Desktop

Дата: 26 ноября 2026. Объём: `apps/desktop/src` (главный процесс, мост, общие типы, интерфейс), README и документы. Аудит только на чтение; исправления войдут в план реализации как этап 0.

Обозначения: **К** — ошибка, которая ломает поведение или безопасность; **С** — структурная проблема, которая мешает развивать код; **Н** — чистота и мелочи.

## 1. Ошибки поведения и безопасности

| # | Где | Проблема | Уровень |
|---|---|---|---|
| 1.1 | `agent/turn.ts`, `main/index.ts` | В историю диалога пишется запрос вместе с блоком `<screen_content>`. Содержимое экрана уходит модели во всех следующих запросах и попадает в сводку. Нарушает правило «экран не сохраняется». | К |
| 1.2 | `agent/turn.ts` | После 4 шагов инструментов последний шаг может закончиться вызовами без текста: пользователь получает пустой ответ. Лимит 4 мал для цепочки «снимок → нажатие → снимок → ввод». | К |
| 1.3 | `main/index.ts` `submit` | Новый запрос прерывает старый, но его ожидающие подтверждения не отменяются: обещания висят, карточка старого запроса может остаться решаемой. | К |
| 1.4 | `main/index.ts` `getProvider` | Ошибка настройки провайдера кэшируется навсегда (`providerError`). Например, если Ollama был выключен при первом запросе, дальше Луна не работает до смены настроек. | К |
| 1.5 | `agent/execute.ts` `update_task` | Статус не проверяется. Неверное значение роняет запрос через ограничение `CHECK` в SQLite. | К |
| 1.6 | `agent/system-tools.ts` `run_command` | Команды получают всё окружение процесса (`process.env`), включая возможные `*_API_KEY`, `OPENAI_API_KEY`, `LUNA_*`. Нужно вычищать секреты. | К |
| 1.7 | `main/secrets.ts` | Ключ передаётся в `security` аргументом командной строки и на мгновение виден в `ps`. Лучше `safeStorage` Electron (ключ шифрования в Keychain, без аргументов). | К |
| 1.8 | `agent/providers.ts` | У некоторых серверов (Ollama) `id` вызова инструмента пустой: подтверждения с одинаковым пустым id перезапишут друг друга. Нужен запасной id. | К |
| 1.9 | `agent/roles.ts`, `tools.ts` | Промпт велит вводить текст «type_text по ссылке», но у `type_text` нет параметра ссылки, а инструмента ввода по ссылке нет. Модель получает невыполнимую инструкцию. | С |
| 1.10 | `main/index.ts` | Пункт меню «Слушать» и состояние «пауза» — заглушки: «Слушать» изображает прослушивание, «Пауза» ничего не останавливает. Вводят в заблуждение. | С |
| 1.11 | `agent/tools.ts` | Описание `web_search` говорит «запрос уйдёт в OpenAI», а по умолчанию поиск идёт в Википедию. | Н |
| 1.12 | `agent/execute.ts` | «Запомнила» написано в женском роде независимо от пола Луны. | Н |

## 2. Структура

| # | Где | Проблема | Уровень |
|---|---|---|---|
| 2.1 | `main/index.ts` (568 строк) | Один файл держит состояние, IPC, провайдера, подтверждения, чтение экрана, память, настройки и запуск. | С |
| 2.2 | агент | Один инструмент описан в пяти местах: схема и риск (`tools.ts`), проверка аргументов (`turn.ts`), выполнение (`execute.ts`, `desktop-dispatch.ts`), правила (`access.ts`). Нужен реестр: у каждого инструмента одно описание — схема, риск, проверка, описание для карточки, выполнение. | С |
| 2.3 | агент | Результат действия — строка; успех определяется по началу текста («Не удалось…»). Нужен результат `{ ok, text }`. | С |
| 2.4 | общие типы | Перечисления (уровни доступа, режимы, статусы задач, слои памяти, пол Луны) объявлены по 2–3 раза: `shared/luna.ts`, `settings.ts`, `access.ts`, `memory/store.ts`. | С |
| 2.5 | глобальное состояние | `foreground`, `explicitThisTurn`, `history`, `conversationSummary` — глобальные переменные, общие для параллельных запросов. | С |
| 2.6 | константы | `HISTORY_LIMIT = 20` в `turn.ts` и `KEEP_RECENT = 12` в `index.ts` описывают одно и то же по-разному. | Н |
| 2.7 | IPC | Канал `luna:panel-view` записан строкой в `windows.ts`, а не через `IPC`. Остались устаревшие каналы `settingsKey`/`saveOpenAIKey`, неиспользуемый `hasProviderKey`. | Н |
| 2.8 | мёртвый код | `AUTO_TOOLS`, `FILE_READ_TOOLS`, `allowKey`, `ACCESS_LEVELS`, `hasOpenAIKey` (почти), двойной импорт из `./agent`, повисший комментарий в `index.ts`. | Н |
| 2.9 | интерфейс | `PanelView.tsx` (522 строки) содержит меню, ввод, подтверждение, память, настройки и разметку ответа; `main.css` (820 строк) без токенов тем. Интерфейс переписывается по спеке полного окна. | С |

## 5. Что сделано хорошо

- Разделение главного процесса и интерфейса через узкий мост (`contextIsolation`, `sandbox`).
- Ключи не попадают в репозиторий и интерфейс.
- Классификатор риска и правила доступа покрыты разовыми проверками и работают.
- Журнал не хранит содержимое экрана и вывод команд.

## 6. Предложение

Этап 0 плана реализации — «стабилизация» до редизайна:
1. Исправить ошибки 1.1–1.8, 1.11, 1.12.
2. Реестр инструментов и результат `{ ok, text }` (2.2, 2.3, 1.9).
3. Единые типы в `shared` (2.4); убрать мёртвый код и устаревшие каналы (2.7, 2.8).
4. Разделить `main/index.ts` на модули (2.1, 2.5) — совпадает с разделом 8 спеки.
5. Vitest и тесты ядра (3.2); ESLint и Prettier без ошибок (3.1).
6. README корня и приложения, обновить SPEC и PLAN (4.x).

Заглушки «Слушать» и «Пауза» (1.10): «Слушать» скрыть до голосовой фазы; «Пауза» должна реально отклонять запросы и показывать это на значке.
